2売れる商品の発見：7法則（データから帰納）

なぜデータ提供者Zは月数万円台稼げるのか。221件のパターンから抽出した原理。

LAW 01
1,000〜3,000円帯で63%回す（資金リスク最小化）

1件あたりの平均仕入れ2,744円。3件売れば1万円分の仕入れが回収。「小ロット高回転」が在宅主婦の正解。

LAW 02
ユニクロは「ダウン」と「ベスト」で買い溜める

ユニクロ35件中、ダウン系は22件以上（推測）。1着545〜2,541円。冬物オフシーズン（3月）にまとめ買い→次の秋冬に備える動きが見える。

LAW 03
ラルフローレン系は通年売れる「鉄板ブランド」

14件が11月〜4月の全月にバラけて出現。POLOロゴはメルカリ需要が安定。初心者の最初の練習ブランドとして最適。

LAW 04
バッグは1月に仕込む

1月のバッグ/財布16件は突出。年明けセール時期＋確定申告前の出品者放出を狙う動き（推測）。客単価が高いため利益貢献度大。

LAW 05
アウトドア3兄弟（ノースフェイス・モンベル・パタゴニア）はキッズも含めて全部買う

モンベル中綿ジャケット110サイズ、ポロバイラルフローレン中綿ジャケットキッズなど、キッズサイズも積極仕入れ。育児層×アウトドアの強いニーズを掴んでいる。

LAW 06
3月の冬物投げ売りを逃さない

3月の73件は他月の倍以上。シーズン切替時の値崩れを買い、次シーズンに売る「タイムマシン仕入れ」。在宅主婦が時間裁量を活かせる戦略。

LAW 07
高額品（5,000円超）は「ブランドバッグ」のみに集中

1万円超2件、5,000〜1万円帯21件のうち、多くはフルラ・コーチ・アグ・キタムラ等のブランドバッグ＆ブランドブーツ。「金額が大きい時はバッグだけ」という判断軸の明快さ。

3-2 確率スコア算出ロジック（A/B/C/D）

100点満点の合計点で4段階判定。

評価軸配点算出方法
データ提供者Z仕入れ実績件数40点10件以上=40 / 5-9件=30 / 2-4件=20 / 1件=10 / 0件=0
出現月の幅（リスクの低さ）20点4ヶ月以上=20 / 2-3ヶ月=12 / 1ヶ月=5
仕入れ値の中央レンジ適合20点1,000-3,000円帯=20 / 3,000-5,000=15 / 〜1,000または5,000-10,000=10 / それ以外=5
カテゴリ平均件数（ジャンル強度）20点カテゴリ件数30以上=20 / 15-29=15 / 5-14=10 / 4以下=5

スコア帯

  • A（80-100点）：迷わず仕入れOK。データ提供者Zが繰り返し買っているブランド／カテゴリ
  • B（60-79点）：仕入れ値レンジを守れば◎。例：フルラ／アグなど高単価ブランド
  • C（40-59点）：シーズン要注意。3月の冬物・4月のサンダルなど時期限定
  • D（〜39点）：データなし or 例外的（高額品・1件のみ）。初心者は避ける

各案の機能詳細

案1：静的JSON+JS

  • UI：シンプル1ページ。検索ボックス＋カード表示
  • データ：seller_data.json（221件構造化済み）＋brand_master.json＋category_master.json
  • 検索：ブランド名・カテゴリ名の部分一致＋スコア計算をJSで実行
  • 更新フロー：担当者→Slackで「新データ追加して」→Claude Codeがjson更新→git push（5分作業）
  • ホスティング：Vercel無料枠でPC・スマホ両対応
  • 課題：ユーザー行動データは取れない（Google Analytics補完）

案2：LIFF+GAS

  • UI：LINEのトーク画面から起動する「ミニアプリ」
  • データ：スプシ（仕入れデータ・マスタ）をGAS APIで配信
  • 検索：GAS doGet()でブランド/カテゴリ検索→JSON返却→LIFFが描画
  • 更新フロー：担当者がスプシ直接編集→即反映
  • 利点：LINEログイン情報で「誰が何を検索したか」全部取得。次回配信のセグメント精度UP
  • 課題：LINE Developers設定＋channel ID取得＋LIFF URL発行＋LINE公式アカウント連携が要る

案3：Claude API

  • UI：Next.js製の本格Webアプリ。検索だけでなく「ノースフェイスの中綿ジャケット女性用Lサイズ」みたいな自然文に対応
  • 検索：Claude Haikuが商品名から意図抽出→ベクトルDB（Supabase pgvector）or BM25で検索
  • 更新フロー：スプシ→Vercel Cron→Embedding再生成
  • 利点：表記ゆれ完全吸収（「TNF」「ノースフェイス」「The North Face」全部同一視）
  • 課題：QA期間が必要。6月本番に間に合わない可能性大

5推奨案＋6月までのスケジュール

推奨：案1（静的JSON+JS）を6月特典として配布、Phase2で案2へ拡張

  1. 6月勉強会まで残り約4週間（推測：6月下旬開催前提）。確実に間に合うのは案1のみ
  2. リソース＝Merone代表（戦略・LP）＋CTO（実装）＋社内スタッフ（コンテンツ）。CTOの稼働を案1なら2日で済ませられる
  3. 6月の目的は「特典としての訴求力」と「データ取得」ではない。まずツール体験を提供→満足度を測る
  4. 案2（LIFF）の本価値である「行動ログ取得」は、まずツール価値検証後に上乗せが筋。最初からLIFFだと「LINE登録ハードル」がツール価値検証を邪魔する
